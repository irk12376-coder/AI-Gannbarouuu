# 自動売買について

## 結論から

**PayPay 証券の口座を自動売買することはできません。**

理由は 3 つです。

1. **公開 API が存在しない。** PayPay 証券は一般利用者向けの注文 API を
   提供していません。法人向け・提携先向けの仕組みはありますが、
   個人が自分の口座を API で操作する手段は用意されていません。
2. **アプリの自動操作は規約リスクがある。** スマホアプリや Web 画面を
   自動操作する方法は技術的には可能ですが、多くの証券会社の利用規約で
   禁止または制限されています。アカウント停止のリスクを負ってまで
   やる価値のあることではありません。
3. **壊れ方が悪い。** 画面の自動操作は、レイアウトが 1 箇所変わるだけで
   誤動作します。誤動作が「注文が出ない」で済めばいいのですが、
   「意図しない注文が出る」方向に転ぶ可能性もあります。

そのため本ツールは、PayPay 証券の口座については
**分析・判定・アラートまで**を担当し、実際の発注は手動で行う設計にしています。
`paystock report` の判定を見て、アプリで自分で売買する、という運用です。

## それでも自動売買したい場合

日本国内で個人が公式に自動売買できる経路として、
**auカブコム証券の kabu ステーション API** に対応しています。

### 仕組み

kabu ステーション (Windows 向けのトレーディングアプリ) を起動すると、
そのアプリが自分の PC の中に REST サーバを立てます。
このツールはそこへ HTTP リクエストを送って発注します。

```
paystock ──HTTP──> localhost:18080 (kabu ステーション) ──> auカブコム証券
```

外部にパスワードを送信することはなく、通信は自分の PC の中で完結します。

### 必要な準備

1. auカブコム証券の口座を開設する
2. kabu ステーションをインストールする (利用条件は同社の案内を確認)
3. kabu ステーション側で API 利用を申し込み、
   **API パスワード**と**注文パスワード**を設定する
4. kabu ステーションを起動したまま、同じ PC でこのツールを動かす

### 設定

パスワードは設定ファイルに書かず、環境変数で渡します。

```bash
export KABU_API_PASSWORD='...'
export KABU_ORDER_PASSWORD='...'
```

`portfolio.yaml`:

```yaml
trade:
  enabled: true
  broker: kabus
  dry_run: true        # まずはドライランで挙動を見る
```

実行:

```bash
python -m paystock trade                 # 検証環境 (ポート 18081)
python -m paystock trade --prod --live   # 本番環境で実発注
```

`--prod` を付けない限り検証環境 (ポート 18081) に接続します。
`--live` を付けない限り発注は行われません。**この 2 つを両方付けたときだけ**
実際のお金が動きます。

### PayPay 証券との違い(重要)

| | PayPay 証券 | auカブコム (kabus) |
| --- | --- | --- |
| 発注単位 | 1,000円 から金額指定 | 原則 100 株単位 (単元株) |
| 小数株 | できる | できない |
| 自動売買 | できない | できる |

**発注単位の違いが実務上いちばん効きます。** 例えば東京エレクトロンを
100 株買うには数百万円が必要です。少額で複数銘柄に分散したいなら
PayPay 証券の金額指定 + 手動売買のほうが現実的です。
自動売買のために証券会社を変えると、分散のしやすさを失う可能性があります。

## 安全装置

自動売買で本当に怖いのは「儲け損ねること」ではなく
「想定外の状況で機械が売買を続けること」です。
そのためエンジンは**迷ったら止まる**方向に倒してあります。

| 安全装置 | 設定項目 | 既定値 | 内容 |
| --- | --- | --- | --- |
| 全体スイッチ | `enabled` | `false` | true にしない限り一切発注しない |
| ドライラン | `dry_run` | `true` | 判断はするが発注はしない |
| キルスイッチ | `kill_switch_file` | `KILL` | このファイルを作れば即停止 |
| 立会時間チェック | `trading_hours_only` | `true` | 東証の取引時間外は動かない |
| 1 発注の上限 | `max_order_amount` | 30,000円 | 1 回の注文金額の上限 |
| 1 銘柄の上限 | `max_position_pct` | 20% | 総資産に対する 1 銘柄の比率上限 |
| 1 日の回数上限 | `max_orders_per_day` | 5 回 | 暴走時の被害を回数で頭打ちにする |
| 1 日の損失上限 | `max_daily_loss_pct` | 5% | 超えたらその日は全面停止 |
| 現金バッファ | `min_cash_buffer` | 1,000円 | これを下回る買付はしない |

### 緊急停止のしかた

```bash
touch KILL      # これだけ。次回の起動時に必ず停止する
```

祝日は判定していないので、祝日に動かしたくない場合は
cron 側で除外するか `KILL` を置いてください。

## 推奨する進め方

いきなり実弾を入れないでください。順番はこうです。

1. **バックテスト** — `paystock backtest` で、そのルールが過去に
   どう振る舞ったかを見る。特に下落局面を含む期間で確認する。
2. **ペーパートレード** — `broker: paper` で最低でも 2〜3 ヶ月動かす。
   バックテストは過去データに都合よく合わせられますが、
   ペーパートレードは未来のデータで動くので嘘がつけません。
3. **少額で実弾** — `max_order_amount` を小さくして始める。
4. **徐々に増やす** — 想定通りに動くことを確認してから金額を上げる。

## 法律面の注意

- 本ツールは自分自身の資産を自分で運用するために使うものです。
  他人の資産を運用したり、他人に売買のタイミングを助言して報酬を得る場合は
  金融商品取引業の登録が必要になります。
- 本ツールの出力は投資助言ではありません。機械的なルールの当てはめ結果です。
- 利用している価格データ (Yahoo Finance / Stooq) は非公式または無保証の
  サービスです。値が欠けたり間違っている可能性を前提に運用してください。
  実発注の前には必ず証券会社の板情報で確認することを勧めます。
